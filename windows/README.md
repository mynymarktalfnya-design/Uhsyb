# تشغيل Windows المحلي

هذه الملفات تشغل النظام محليًا على Windows دون الاعتماد على Replit أو تبويب متصفح مفتوح. يقوم المشرف المحلي بتشغيل API والواجهة، ويراقب الاتصال، ويشغل بوت Telegram فقط عند توفر الإنترنت ووجود إعداداته المحفوظة في إعدادات المدير. النسخ الاحتياطي المحلي ومزامنة Google Drive يبقيان داخل خادم API، وفشلهما لا يوقف النظام.

## المتطلبات

يجب تثبيت Python 3.11 أو أحدث وNode.js وpnpm، ثم تثبيت الاعتماديات من جذر المشروع. لا يوجد رابط قاعدة بيانات أو Token داخل هذه الملفات. يحدد المدير قاعدة البيانات من **إعدادات النظام → اختبار وربط الآن**.

## التشغيل

من PowerShell داخل مجلد المشروع:

```powershell
$env:JWT_SECRET_KEY = "ضع مفتاحًا سريًا محليًا قويًا هنا"
.\windows\start-local.ps1
```

لا تحفظ المفتاح في GitHub ولا ترسله في سجل الأوامر. في التشغيل الدائم، خزنه في Windows Credential Manager أو متغير بيئة مستخدم محمي بدل وضعه في ملف عام.

## التشغيل التلقائي

شغّل PowerShell بصلاحية مناسبة ونفذ:

```powershell
.\windows\install-local.ps1
Start-ScheduledTask -TaskName "MiniMarketAlFaniya"
```

إلغاء التشغيل التلقائي:

```powershell
.\windows\uninstall-local.ps1
```

السجلات المحلية تكتب في `windows/logs` ولا يجب رفعها إلى GitHub.

## قاعدة البيانات

لا يختار المشرف نوعًا نيابة عن المدير. تبقى آلية الربط الحالية كما هي، وتدعم الأنواع التي لها Adapter داخل النظام. لا يعني إدخال أي رابط عشوائي أن النظام يدعم ذلك النوع؛ إضافة نوع جديد تحتاج Adapter وDriver واختبارات خاصة.

## حالة التنفيذ

`offline_store.py` يوفر مخزنًا دائمًا مستقلًا عن المتصفح باستخدام SQLite وWAL، مع الحالات `Pending`, `Syncing`, `Synced`, `Failed` وOperation ID فريد. ربط كل mutation في واجهة النظام بهذا المخزن بدل IndexedDB فقط هو المرحلة التالية، ويجب اختباره على Windows فعليًا قبل اعتبار الحزمة جاهزة للإنتاج.
